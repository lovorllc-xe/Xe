XeLang: language guide and first course
=======================================

This guide introduces the XeLang syntax implemented by Stage 0 and Stage 1.
The language spelling is the same in both stages: Stage 0 is the C++ interpreter
and host compiler; Stage 1 is the compiler written in XeLang.

The assignment operator is :=. The equality comparison operator is =. XeLang
does not use ==. GPU offload and fix<N> are currently unsupported.

1. Install and run the compilers
--------------------------------

Build Stage 0 from the project root:

    cmake -S . -B build
    cmake --build build

Run a program with the interpreter:

    ./build/xe --run hello.xe

Build a native host executable:

    ./build/xe --build hello.xe -o hello.xee
    ./hello.xee

Build Stage 1 with Stage 0:

    ./build/xe --build \
      compiler/token.xe compiler/lexer.xe compiler/ast.xe compiler/parser.xe \
      compiler/checker.xe compiler/codegen.xe compiler/optimizer.xe \
      compiler/runtime.xe compiler/main.xe -o xelang-stage1

Stage 1 can emit or build Linux x86-64 GAS and NASM programs:

    ./xelang-stage1 --emit-asm hello.xe -o hello.s
    ./xelang-stage1 --build hello.xe -o hello
    ./xelang-stage1 --emit-nasm hello.xe -o hello.asm
    ./xelang-stage1 --build-nasm hello.xe -o hello-nasm
    ./xelang-stage1 --run hello.xe

It also has freestanding output modes for simple programs without runtime calls:

    ./xelang-stage1 --build-pe hello.xe -o hello.exe
    ./xelang-stage1 --build-baremetal hello.xe -o hello.bin

PE and bare-metal output require their platform tools. Both freestanding modes
reject programs that use runtime I/O, allocation, or GC. User-defined helper
functions can accept parameters. Linux ELF is the general runtime target.

2. A first program
------------------

Save this as hello.xe:

    fn main(): int
    begin
        writeln("Hello, XeLang!")
        return 0
    end

A program starts in fn main. A function body uses begin and end. The function
returns an integer process status. writeln prints its value and a newline; write
prints without adding a newline.

3. Lines, comments, names, and blocks
-------------------------------------

Newlines end statements. A semicolon continues the current statement onto the
next line; it is not a line terminator:

    var result: int := 10 + ;
        20

Write comments with //:

    // This line is ignored by the compiler.

Identifiers may contain letters, digits, and underscores. Use dots for
namespaces and multi-part names, such as text.length or geometry.point. Dots
also work in variable and function names where a name is expected.

Large blocks use begin/end: functions, modules, and switches. Small control
blocks use braces:

    if result > 20 {
        writeln("large")
    } else {
        writeln("small")
    }

    while result > 0 {
        result := result - 1
    }

Indentation makes code easier to read, but it does not define the block.

4. Values, types, and variables
-------------------------------

XeLang's principal types are:

    int       signed 64-bit integer
    flt       64-bit floating-point number
    *T        raw pointer to a value of type T
    [N]T      fixed-size array of N values of type T
    string    text value used by the runtime
    void      no return value

Declare a variable with var, a name, a colon, and its type. An initializer is
optional:

    var score: int := 42
    var price: flt := 19.95
    var title: string := "XeLang"
    var next: *int
    var samples: [3]int

Use const for an immutable local binding. It requires an initializer, and the
binding cannot be reassigned or changed through a field or array element:

    const answer: int := 42

Types can be nested. For example, [2][4]flt is an array of two arrays, each
containing four floating-point values.

Type aliases give a longer type a short name:

    type Score: int
    var best: Score := 100

Stage 0 and Stage 1 support module and program aliases, including aliases
declared in a different source file in the same compiler invocation. Stage 1
rejects ambiguous alias definitions and still accepts a narrower type subset
than Stage 0.

Value records with named fields are supported. Declare a record with
`type Name: record`, then use dot access to read or update its fields:

    type Point: record
    begin
        x: int
        y: int
    end

    var point: Point
    point.x := 12
    point.y := 30
    writeln(point.x + point.y)

Records can contain other record values. The self-hosted compiler supports
record declarations, nested fields, local values, and record values passed to
and returned from functions, along with pointer-based field access.

Both compiler implementations check const local bindings. This provides
binding immutability, not compile-time evaluation or immutable references.

5. Assignment, arithmetic, and comparisons
------------------------------------------

Use := to assign a value or update a variable:

    var count: int := 3
    count := count + 1

Use = to compare values for equality. Other comparisons are !=, <, >, <=, and
>=. Logical operators are &&, ||, and !:

    if count = 4 && !(count > 10) {
        writeln("four")
    }

Arithmetic operators are +, -, *, /, and %. Parentheses can make grouping
clear. Multiplication and division bind more tightly than addition and
subtraction:

    var value: int := 2 + 3 * 4       // 14
    var same: int := value = 14       // 1 (true)

Comparisons return an int value: 1 means true and 0 means false. Integer
division produces an integer when both operands are int. Floating-point
arithmetic and comparisons use flt values; Stage 1 also permits mixed int/flt
numeric comparisons:

    var total: flt := 1.5 * 2.25 + 0.75
    var isLarge: int := total >= 5
    writeln(total)

6. Functions and modules
------------------------

Functions can accept typed parameters and return a value:

    fn add(left: int, right: int): int
    begin
        return left + right
    end

    fn main(): int
    begin
        writeln(add(20, 22))
        return 0
    end

A function without an explicit result type returns void. Return a value with
return, or use a bare return in a void function.

Group declarations in a module. The module name becomes a namespace prefix:

    module math
    begin
        fn square(value: int): int
        begin
            return value * value
        end
    end

    fn main(): int
    begin
        return math.square(7) - 49
    end

Both compiler paths combine multiple source files and check aliases across
those files.

Stage 0 can resolve separate source library units through a top-level `uses`
declaration. `libraries/collections.xel` provides a dynamic pointer sequence, a
bounded string-to-pointer hash map, and bounded integer stack and vector
records. `libraries/algorithms.xel` imports it and provides integer sorting,
searching, and summation. `libraries/sys.xel` wraps memory operations, volatile
hardware access, Linux process calls, and a manually managed byte buffer;
`libraries/syscall.xel` exposes raw Linux x86-64 syscalls and file descriptor
I/O; `libraries/bitops.xel` wraps bitwise arithmetic. `libraries/string_utils.xel`
provides trimming, splitting, joining, and integer parsing;
`libraries/math.xel` provides scalar helpers; `libraries/net.xel` wraps Linux
IPv4 socket calls. `uses collections` loads `collections.xel`
beside the importing file, or from a directory passed with `--library-path`:

    uses math

    fn main(): int
    begin
        writeln(math.twice(21))
        return 0
    end

The library file can define its namespace with `module collections begin ... end`.
Both compiler paths follow imports recursively and combine the loaded source
units for this build; neither produces reusable compiled library artifacts. The
pointer vector grows its heap array geometrically and supports constant-time
indexed lookup. It stores opaque pointer values using Stage 0 pointer-slot
runtime operations. The pointer map uses linear probing with a fixed 128-slot
capacity. String splitting returns manually allocated string pointers; call
`string_utils.free.parts` when finished, or allocate/use the result within a GC
region. The IPv4 socket wrappers target Linux x86-64. The integer stack and
vector remain bounded. The self-hosted compiler resolves `uses` dependencies
from the importing directory or a directory passed with `--library-path`.

7. Decisions, loops, and switches
---------------------------------

An if statement may have an else block:

    if temperature > 30 {
        writeln("warm")
    } else {
        writeln("cool")
    }

Use while for a condition-controlled loop:

    var index: int := 0
    while index < 3 {
        writeln(index)
        index := index + 1
    }

Use switch with case labels and an optional default. A matching case runs and
then control leaves the switch:

    switch index begin
        case 0
            writeln("zero")
        case 1
            writeln("one")
        default
            writeln("other")
    end

Control blocks can be nested. Stage 1 lowers nested if, while, and switch
statements to assembly for the supported scalar and array subset. Stage 0
interprets and compiles nested blocks directly.

Each brace-delimited block has its own local-variable scope. A local declared
inside an if, while, switch arm, or GC block is available until that block
ends. An inner block may shadow an outer local; after the inner block ends,
the outer local is visible again:

    var amount: int := 10
    if amount = 10 {
        var amount: flt := 2.5
        writeln(amount)
    }
    writeln(amount)       // prints the outer integer, 10

Declaring the same name twice in one block, or repeating a parameter name, is
an error in both stages.

8. Arrays and slices
--------------------

Declare a fixed-size array and access each element with brackets:

    var values: [3]int
    values[0] := 8
    values[1] := 13
    values[2] := values[0] + values[1]
    writeln(values[2])

Indexing starts at zero. The self-hosted compiler emits stack-backed fixed-size
arrays of int and flt. Float elements support reads, writes, and arithmetic:

    var weights: [2]flt
    weights[0] := 1.5
    weights[1] := 2.25
    writeln(weights[0] + weights[1])

Array values are stored inline up to their declared capacities and retain their
current length across assignments, calls, records, and slices. Indexing and
slicing check this length. Arbitrary pointer bounds checks are not implemented.

Array slices use a half-open range: the first
index is included and the final index is excluded. For example, values[1:3]
contains elements 1 and 2. Use a slice where an array value is expected.

9. Strings and text helpers
---------------------------

Use quoted strings for text. Escape newline, tab, carriage return, backslash,
and quote characters as needed. Strings can be printed and joined with +:

    var greeting: string := "Hello"
    writeln(greeting + ", XeLang!")

The text helpers are:

    str.length(text)             number of bytes before the zero terminator
    str.char(text, index)        numeric byte at index
    str.slice(text, first, last) copy a half-open range
    str.find(text, search)       first matching index, or -1
    str.number(value)            integer converted to text
    str.fromchar(value)          one-byte string
    str.builder(initial)         mutable text builder
    str.append(builder, text)    append text and return the builder

Builders are useful for producing long text without repeatedly copying the
whole string. Stage 1's own source uses them for assembly generation.

10. Input and output
--------------------

write and writeln print values. Both stages accept multiple values per call.
Stage 1 supports integer, floating-point, string, and pointer values:

    write("The answer is ")
    writeln(42)
    writeln(3.125)
    writeln("total: ", 42, ", price: ", 3.125)

read reads an int or flt variable. readln reads the rest of the current input
line into a string variable:

    var age: int := 0
    var comment: string := ""
    read(age)
    readln(comment)
    writeln("Age: " + str.number(age))
    writeln(comment)

read consumes the value and its next whitespace character. readln then reads
the remaining text on that line. If the value is followed by a newline, readln
reads the following line. Input errors are reported by Stage 0; Stage 1's
syscall runtime uses zero or an empty string at end of input.

11. Pointers, allocation, and regional GC
-----------------------------------------

A pointer type begins with *. Use alloc to request bytes and free to release a
manual allocation:

    fn main(): int
    begin
        var address: *int := alloc(8)
        *address := 73
        writeln(*address)
        free(address)
        return 0
    end

Stage 0 also provides `new(size)` as an allocation alias, `delete(pointer)` as
a deallocation alias, and `aligned_alloc(size, alignment)` for aligned raw
memory. Alignment must be a power of two and at least the platform pointer
alignment. For example:

    var block: *int := aligned_alloc(128, 64)
    delete(block)

The original `alloc`, `free`, and `alloc.aligned(size, alignment)` names remain
available in both compiler paths.

Pointers to flt values also support floating-point loads and stores:

    var address: *flt := alloc(8)
    *address := 3.5
    writeln(*address)
    free(address)

The address-of operator & takes the address of a variable. The dereference
operator * reads or writes a pointed-to value. Stage 0 performs type and
lifetime checks for pointer values in supported cases. Raw hardware access is
available through @ and # in Stage 0; it is unsafe and depends on the target
machine and process permissions.

A regional GC scope releases allocations made in the region when the scope
ends:

    gc.begin {
        var temporary: *int := alloc(64)
        // Use temporary only while this region is active.
    }
    gc.end

Stage 0 also supports aligned raw allocation and scope-exit cleanup:

    var block: *int := alloc.aligned(128, 64)
    defer free(block)

`alloc.aligned(size, alignment)` requires a nonnegative size and a power-of-two
alignment at least the platform's pointer alignment. `defer` accepts a procedure call and runs
it when the current lexical scope exits, including when control returns early.
Deferred calls run in reverse declaration order. Use `defer free(pointer)` to
make a manual allocation follow a deterministic cleanup path.

Aligned allocation and `defer` are supported by both compiler paths.

Stage 0 tracks nested regions. Stage 1 provides a native arena runtime and
restores the allocation cursor at gc.end. Do not return or retain a pointer to
region-owned data after the region closes. A helper can safely read a region
pointer:

    fn read.value(value: *int): int
    begin
        return *value
    end

Stage 0 and Stage 1 reject detected pointer escapes through returns, longer
lived assignments, and calls whose bodies may retain the pointer. Stage 1
allows calls to helpers that only read the pointer. Inline assembly is opaque
to this analysis, so do not use it to retain a region pointer.

12. Inline assembly
-------------------

asm introduces a raw assembly block. Its contents are passed through to the
native output without XeLang name or underscore processing:

    fn shift.value(value: int): int
    begin
        asm {
            mov rax, rdi
            shl rax, 1
        }
        return value * 2
    end

Inline assembly is target-specific. Match the active target's assembly syntax
and calling convention. Stage 0 places the block in a compiler-generated C++
inline-assembly expression; the host compiler must support that syntax.

13. Runtime helpers
------------------

The following helpers are available in both compiler paths on Linux, subject
to target-specific restrictions:

    alloc(bytes)                 allocate raw bytes; returns a pointer
    free(pointer)                release a manual allocation
    write(values...)             print values
    writeln(values...)           print values and a newline
    read(variable)               read an int or flt
    readln(stringVariable)       read a line
    flt.format(value, decimals)  format a float with fixed decimals
    arg.count()                  number of program arguments
    arg.get(index)               program argument text
    file.read(path)              read a file as text
    file.write(path, text)       write text to a file
    process.run(command)         run a host command and return its status

String helper functions are listed in section 9. The self-hosted command driver
uses file, argument, and process helpers; programs compiled by it use its Linux
syscall runtime. Some helpers may be rejected for PE and bare-metal output.

14. Stage 0 and Stage 1 behavior
--------------------------------

Stage 0 is implemented in C++20. It parses complete nested AST blocks, checks
symbols and types, interprets programs, and builds host executables through a
C++ compiler. Use Stage 0 to run programs or to bootstrap Stage 1.

Stage 1 is implemented in XeLang. It parses and checks its supported source
subset, emits x86-64 assembly, includes its own runtime routines, and uses a
linear-scan style allocation pass for integer locals. The Linux GAS/ELF backend
is the general Stage 1 target. The Linux NASM/ELF backend converts emitted GAS
syntax to NASM syntax. PE and bare-metal builders currently accept a
freestanding subset only.

The self-hosted Linux compiler supports the records, arrays, and other forms
listed above. PE and bare-metal targets accept only their documented
freestanding subsets. The project intentionally does not support GPU offload
or fix<N>.

15. Practice tasks
------------------

1. Write a function that converts Celsius to Fahrenheit using flt.
2. Store five integers in an array and compute their sum with while.
3. Read a number, use switch to choose a message, and print it.
4. Create a module with a function and call it from main.
5. Allocate a pointer inside a GC region and use it before gc.end.

A complete small example:

    fn sum.values(limit: int): int
    begin
        var values: [3]int
        values[0] := 2
        values[1] := 3
        values[2] := 5
        var index: int := 0
        var total: int := 0
        while index < 3 {
            total := total + values[index]
            index := index + 1
        }
        return total - limit
    end

    fn main(): int
    begin
        writeln(sum.values(10))
        return 0
    end
